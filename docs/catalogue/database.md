# database

A managed relational database that compute nodes read from and write to. Postgres or MySQL. Private, encrypted, credentials owned by the platform.

Properties: engine, version, size, storageGb, highAvailability.

## AWS

- `aws_db_subnet_group` over the private subnets of the implicit VPC. The first node that needs the private network creates that VPC, with a single NAT gateway that costs roughly 30 US dollars a month before data charges. Subnets are spread over the first two availability zones returned by the `aws_availability_zones` data source, so the network adapts to whichever region the project targets rather than hardcoding zone names.
- `aws_security_group` with no rules of its own. Ingress rules come from `reads` and `writes` edges.
- `aws_db_instance` with `manage_master_user_password = true`, so RDS creates and rotates the secret and nothing sensitive lives in state or in the generated code. Storage encrypted, not publicly accessible, seven day backups. `skip_final_snapshot` and `deletion_protection = false` because this is a scaffold and `terraform destroy` should work.
- Output `<name>_endpoint`.

Sizes: small `db.t4g.micro`, medium `db.t4g.medium`, large `db.r6g.large`. `highAvailability` sets `multi_az`.

Engine versions allowed: postgres 17, 16, 15. MySQL 8.4, 8.0. Default is the first. The table lives in `ir.Engines`, keyed by provider, and `just generate` publishes it as `schema/engines.json` for the editor. `ValidateProject` rejects a version the provider does not list, and the AWS resolver checks again on the way through.

A `reads` or `writes` edge from a function adds an ingress rule from the function's security group on the engine port, an IAM statement allowing `secretsmanager:GetSecretValue` on the managed secret, and the env vars `<NAME>_HOST`, `<NAME>_PORT`, `<NAME>_NAME`, `<NAME>_SECRET_ARN` on the function. The function is placed in the VPC.

Cost: `togen cost` prices a database as two meters from the bundled RDS list prices. The instance is 730 hours a month of the `Database Instance` SKU for the size's instance class, the engine, `Single-AZ` or `Multi-AZ` from `highAvailability`, on demand, in the project's region. Storage is `storageGb` GB-months of `General Purpose` (gp2), which is what `aws_db_instance` provisions when no `storage_type` is set, with the same engine and deployment option, so Multi-AZ doubles both meters as AWS bills them. The engine version does not change the price and is shown only in the summary. A database takes no usage keys; its storage is the `storageGb` property, so an entry for it in the `usage` block fails validation. Backups beyond the allocated size, I/O, snapshot exports and data transfer are not priced, and the output says so. The first node that needs the VPC also brings the NAT gateway's hourly charge under `network`, and `natGb` under the `network` usage key prices the data it processes. The matcher is `internal/resolve/aws/cost.go`, beside the size table, so a change to the sizes and its price consequence are one diff.

## GCP

- `google_sql_database_instance` named `<project>-<environment>-<name>` in the project's region, with `database_version` `POSTGRES_<n>` or `MYSQL_<n>` from the engine table. It has a private address only: `ip_configuration` turns `ipv4_enabled` off and points `private_network` at the implicit VPC, and the instance carries an explicit `depends_on` on the service networking connection, because Terraform cannot see from its arguments that the peering has to exist first. The first node that needs the private network creates the VPC, its subnet, the VPC access connector, the reserved range and the peering. `settings.edition` is `ENTERPRISE`, said explicitly because Cloud SQL defaults Postgres 16 and later to Enterprise Plus, which refuses the shared-core and custom tiers below. `deletion_protection = false`, as on AWS, so `terraform destroy` works.
- `google_sql_database` named after the node with hyphens as underscores, on that instance.
- `random_password`, 32 characters with special characters off, and a `google_sql_user` `app` that takes it. The password lives in Terraform state. On AWS `manage_master_user_password` keeps it in Secrets Manager instead; ADR 0010 defers Secret Manager here until the secrets story is designed. The `random` provider (`hashicorp/random ~> 3.6`) joins `required_providers` the first time a node needs it, once however many databases there are.
- Output `<name>_connection_name`, the `project:region:instance` string the Cloud SQL Auth Proxy takes.

Sizes: small `db-f1-micro` (shared core, 0.6 GB, outside the Cloud SQL SLA the way the AWS micro is burstable), medium `db-custom-2-7680` (2 vCPU, 7.5 GB), large `db-custom-4-15360` (4 vCPU, 15 GB). Custom tiers are `db-custom-<vcpu>-<mb>` with memory a multiple of 256 MB between 0.9 and 6.5 GB per vCPU, and these two are the standard shapes Google documents. `storageGb` is `disk_size` with `disk_autoresize` off, so the size in the sketch is the size on disk and a later apply does not try to shrink a disk Cloud SQL grew. `highAvailability` sets `availability_type` to `REGIONAL` rather than `ZONAL`.

Engine versions allowed: postgres 17, 16, 15 (`POSTGRES_17` and so on), MySQL 8.4, 8.0 (`MYSQL_8_4`, `MYSQL_8_0`). Default is the first. Cloud SQL also offers Postgres 18 and MySQL 9.7 (checked 2026-09-06); they are left out so the table matches the AWS one. `ValidateProject` rejects a version the provider does not list, and the GCP resolver checks again on the way through.

Cloud SQL keeps a deleted instance's name for about a week, so a destroy followed by an apply with the same names waits that long or needs a different environment name.

A `reads` or `writes` edge from a function sets `<NAME>_HOST` (the private address), `<NAME>_PORT`, `<NAME>_NAME`, `<NAME>_USER` and `<NAME>_PASSWORD` on the function and puts it on the VPC access connector. There is no port to open and no role to grant: the instance answers anything on the VPC, and access is the user and password. Reads and writes wire the same way, since one user owns the database. A service will be wired the same way once the GCP resolver has one: a Cloud Run service exports the same handle as a function, so the edge already takes it.

The generated code does not enable APIs. The GCP project needs the Cloud SQL Admin, Service Networking and Serverless VPC Access APIs enabled before the first apply.

Cost: `togen cost` prices a database on the Cloud SQL meters, once a GCP snapshot is bundled. A shared core tier (`db-f1-micro`) is one hourly meter, `Cloud SQL for <engine>: <availability> - Micro instance`, at 730 hours a month. A custom tier is two meters, `vCPU` at the tier's cores times 730 and `RAM` at its gigabytes times 730. Storage is `storageGb` GB-months of `Standard storage`. `highAvailability` moves every meter from the `Zonal` set to the `Regional` one, which Google prices at about twice the rate, so it doubles the item the way Multi-AZ does on AWS. The engine version does not change the price and is shown only in the summary. A database takes no usage keys. Backups are not priced and the output says so. The first node that needs the VPC also brings the access connector's instance hours under `network`. The matcher is `internal/resolve/gcp/cost.go`, beside the tier table, so a change to the tiers and its price consequence are one diff.

## Azure

- `azurerm_postgresql_flexible_server` or `azurerm_mysql_flexible_server` in the resource group every Azure project gets, on the implicit virtual network's delegated subnet for its engine. The network always carries `azurerm_subnet.postgres` (`10.0.2.0/24`, delegated to `Microsoft.DBforPostgreSQL/flexibleServers`). A subnet takes one delegation, so the first MySQL database adds `azurerm_subnet.mysql` (`10.0.3.0/24`, `Microsoft.DBforMySQL/flexibleServers`), and a project without MySQL never gets it.
- `azurerm_private_dns_zone` named `<project>-<env>-<name>.postgres.database.azure.com` or `.mysql.database.azure.com`, the domain the flexible servers insist on, with an `azurerm_private_dns_zone_virtual_network_link` to the virtual network. The server takes `delegated_subnet_id` and `private_dns_zone_id` and carries `depends_on` for the link, because Azure refuses a server whose zone is not linked yet and nothing in the server's own arguments refers to the link. Public network access is off.
- `random_password`: 32 characters, no special characters, at least one lower case letter, one upper case and one digit. Both servers want three character classes and a 32 character draw from three misses one about once in a hundred, so each is guaranteed. It is the `administrator_password`; the login is `app`. This is the first use of the `random` provider, which the graph lists in `required_providers` once however many databases there are.
- `azurerm_postgresql_flexible_server_database` with the provider's defaults (`UTF8`, `en_US.utf8`), or `azurerm_mysql_flexible_database` with `utf8mb4` and `utf8mb4_unicode_ci`, which the provider requires and which both 5.7 and 8.0 have.
- Output `<name>_fqdn`, the server's fully qualified domain name.

Sizes: small `B_Standard_B1ms` (burstable, one vCore, 2 GiB), medium `GP_Standard_D2ds_v4` (general purpose, two vCores, 8 GiB), large `GP_Standard_D4ds_v4` (four vCores, 16 GiB). The same names serve both engines. `highAvailability` adds a `high_availability` block with `mode = "ZoneRedundant"`. The burstable tier has no standby, so `highAvailability` on a small database is refused rather than written for Azure to reject at apply.

Storage: Postgres sells disks in tiers, 32, 64, 128 GiB and so on up to 32 TiB, so `storageGb` rounds up to the first tier that holds it and `storage_mb` carries that. The default 20 GB is a 32 GiB disk. MySQL takes the number as given, as `size_gb` in the `storage` block.

Engine versions allowed: postgres 17, 16, 15, MySQL 8.0.21 and 5.7, as the flexible servers name them. Default is the first. The provider accepts more (Postgres 18 and 11 to 14, MySQL 8.4); the list keeps the three Postgres majors AWS has and the two MySQL lines Azure has run longest, and grows when asked. `ValidateProject` rejects a version outside the list and the resolver checks again on the way through.

A `reads` or `writes` edge from a function sets the app settings `<NAME>_HOST` (the server's FQDN), `<NAME>_PORT`, `<NAME>_NAME`, `<NAME>_USER` and `<NAME>_PASSWORD` on the function app and marks it as needing the network. The consumption plan has no virtual network integration and the private DNS zone only answers from inside the network, so a Y1 function app carries the right settings but cannot reach the server until it moves to a plan that joins the network. A service is already in it (the Container Apps environment sits on the `apps` subnet), and the same edge sets the same five names in its container env.

Cost: `togen cost` prices a database as two meters from the bundled Azure retail prices. Compute for the small size is 730 hours a month of the `B1MS` meter under `Azure Database for <engine> Flexible Server Burstable BS Series Compute`; medium and large are the General Purpose series' `vCore` meter, 730 hours times the size's two or four vCores, so one meter serves both sizes. Storage is `Storage Data Stored` on the flexible server's storage product, in GB-months, at the size Terraform actually provisions: Postgres rounds `storageGb` up to its disk tier, so the default 20 GB is priced as 32. `highAvailability` runs a standby with its own compute and storage, so both meters double and the summary says `zone redundant`. The engine version does not change the price and is shown only in the summary. A database takes no usage keys; its storage is the `storageGb` property, so an entry for it in the `usage` block fails validation. Backups beyond the allocated storage, IOPS beyond the ones the tier includes, and the private DNS zone's queries are not priced, and the output names the backups. The virtual network is free and nothing here creates a NAT gateway, so unlike AWS a database brings no implicit charge with it. The matcher is `internal/resolve/azure/cost.go`, which keeps a meter per engine and size beside the size table in `sizes.go`, so a new size needs the meter that prices it.
